# Инструкции для ИИ-агентов

Этот файл читают агенты (Claude Code, Codex, Cursor и др.) перед работой с репозиторием. Описание сделанных улучшений для людей — в [README.md](README.md).

## Что это за проект

Модифицированная сборка десктоп-приложения **DesktopUmagFX 4.1.0** (JavaFX + Spring + Hibernate + HSQLDB) для загрузки товаров на электронные весы (Rongta, CAS, Massa-K, Mertech, Tiger, Штрих и др.).

**Исходников Java в репозитории нет.** Работа ведётся с распакованным JAR: ресурсы правятся как текст, а логика — патчами байткода через Javassist.

## Структура

| Путь | Что там |
|---|---|
| `lib/DesktopUmagFX-4.1.0.jar` | Основной JAR приложения — **результат сборки**, его запускает `.bat` |
| `lib/*.jar` | Зависимости (в т.ч. `javassist`, нужный скриптам патчей) |
| `_extracted/` | Изменённые файлы JAR — здесь вносятся правки; **всё** отсюда попадает в JAR |
| `_extracted/layout/*.fxml` | Разметка экранов JavaFX |
| `_extracted/styles/common.css` | Общие компоненты светлой темы (кнопки, поля, таблицы, диалоги) — подключается первым в каждом FXML |
| `_extracted/styles/*.css` | Стили отдельных экранов; `dark.css` — тёмная тема |
| `_extracted/image/` | Новые изображения (например, светлый логотип для тёмной темы) |
| `_extracted/kz/umag/scale/**.class` | Скомпилированные классы (часть пропатчена) |
| `patch_ui.js` | Актуальные патчи байткода (Javassist под Nashorn), **идемпотентен** |
| `patch_senior.js` | Исторические патчи; уже применены, повторно не запускается (сам себя пропускает) |
| `repack_final.js` | Пересборка JAR из `_extracted/` |
| `bin/DesktopUmagFX.bat` | Запуск приложения (главный класс `kz.umag.scale.app.ScaleApp`) |
| `bin/db/`, `db/` | Локальная база HSQLDB (`scale.script`, `scale.properties`) |
| `configs/libra.properties` | Конфигурация весов |
| `jre/` | Встроенная Java 8 (32-bit), **не в git** — см. ниже |

## Окружение

- Только **Windows**. Приложение использует нативные DLL драйверов весов через JNA.
- Нужна **Java 8** (с JavaFX и Nashorn/`jjs`). Каталог `jre/` исключён из git (`.gitignore`), после клонирования его надо положить в корень вручную — `.bat` ищет именно `jre\bin\java.exe`.
- Скрипты находят репозиторий через `__DIR__` (папку самого скрипта) — жёстко прописанных путей нет.

## Рабочий цикл

1. **Правка ресурсов** — редактируй файлы в `_extracted/layout/` и `_extracted/styles/`.
2. **Правка логики** — добавь патч в `patch_ui.js` и запусти его (классы записываются в `_extracted/`):
   ```bat
   jre\bin\jjs.exe -cp lib\javassist-3.24.0-GA.jar patch_ui.js
   ```
3. **Пересборка JAR** (приложение должно быть закрыто):
   ```bat
   jre\bin\jjs.exe repack_final.js
   ```
4. **Запуск и проверка**:
   ```bat
   cd bin
   DesktopUmagFX.bat
   ```

Автотестов нет. Проверка — запуск приложения и ручной просмотр изменённого экрана **в обеих темах**; ошибки смотри в консоли и в `bin/logs/store.log`.

## Как устроена тема

- Светлые стили — в `common.css` и CSS экранов, подключённых к корню FXML (`stylesheets="@../styles/common.css, @../styles/xxx.css"`).
- `dark.css` подключается **к сцене** каждого окна классом `kz.umag.scale.ui.Theme` (создаётся `patch_ui.js`). `Theme.install()` вызывается в начале `ScaleApp.start()` и через `StageHelper.getStages()` применяет тему ко всем окнам, включая открытые позже диалоги. Выбор хранится в `java.util.prefs` (`HKCU\Software\JavaSoft\Prefs\kz\umag\scale`).
- В JavaFX таблица стилей, подключённая к узлу, **побеждает** таблицу сцены при равной специфичности. Поэтому каждый селектор в `dark.css` начинается с `.root ` (для самого корня сцены — `.root.<класс>`). Новое правило со цветом в светлом CSS => пара в `dark.css` с тем же селектором и префиксом `.root`, включая псевдоклассы (`:hover`, `:selected`).
- У узла `Text` из FXML **нет** CSS-класса `.text` — цвет задавай своим классом (`bodyText`, `mutedText`, `dialogTitle`, …).
- Цвета, которые ставит код, CSS не перекрывает: инлайн-стиль (`setStyle`) сильнее любого CSS. Код диалогов пропускает такие значения через `Theme.inlineStyle()` / `Theme.textColor()`; ячейки таблицы вместо инлайн-цвета получают класс `cellError`.

## Код зависит от структуры FXML

Меняя разметку, сохраняй все `fx:id` и обработчики `#метод`, а также:

- `sync.fxml`: первые два ребёнка `scalePane` — `addScaleButtonPrimary` и `addScaleButtonSecondary` (`cleanToggles()` удаляет детей начиная с индекса 2); дети `infoContainer` — только `VBox` (`setHelpDesk()` приводит их к `VBox`).
- `login.fxml`: корень `HBox` → первый ребёнок `VBox` → его первый ребёнок `AnchorPane` (туда добавляется экранная клавиатура).
- `products.fxml`: корень — `AnchorPane` (туда добавляется экранная клавиатура).
- `modal_dialog.fxml`: `ModalDialogNew` ищет узлы по id (`container`, `titleText`, `primaryButton`, …) и сам задаёт размеры.

## Важные ловушки

- **`patch_ui.js` должен оставаться идемпотентным**: тела методов меняй через `setBody`, а вставки (`insertBefore`/`insertAfter`/`instrument`) оборачивай в `once(...)` — она ставит в класс поле-маркер `UMAG_PATCH_UI`. Для нового набора вставок в уже помеченный класс заведи новый маркер.
- **Записывай классы через `save(ct)` из `patch_ui.js`**, а не `ct.writeFile(...)`: `writeFile` в тот же каталог, из которого класс читается, может обрезать файл (так `StagedControl.class` обрезался до 8192 байт).
- **Javassist не понимает `\u`-экранирование в строках Java-кода**: `"\\u2600"` превращается в текст `u2600`. Пиши символы напрямую, через `\u`-экранирование JavaScript или `String.valueOf(Character.toChars(0x2600))`.
- **`-cp "lib\*"` работает только в `cmd.exe`.** В PowerShell и Git Bash лаунчер Java раскрывает `*` в список файлов, и `jjs` пытается выполнить JAR-ы как скрипты. Указывай конкретный JAR (`-cp lib\javassist-3.24.0-GA.jar`).
- **FXML — строго UTF-8 без BOM** и без пустых строк перед `<?xml ...?>`. Осторожно с PowerShell 5.1: `Out-File`/`>` добавляют BOM.
- **Не используй инлайн-стили `style="..."` в FXML** — они перекрывают CSS-классы и ломают тёмную тему.
- **Javassist-код — это Java 1.4-подобный синтаксис**: без дженериков, лямбд, автобоксинга и инициализаторов массивов; параметры метода — `$1`, `$2`; вложенные классы — через `$` (`ListChangeListener$Change`); имена классов — полностью квалифицированные.
- Байткод должен оставаться совместимым с **Java 8**.
- **Закрой приложение перед пересборкой** — запущенный процесс держит JAR и файлы базы (`*.lck`).
- `repack_final.js` заменяет JAR на месте. Резервная копия `lib/*.bak` в git не хранится; для отката используй `git checkout -- lib/DesktopUmagFX-4.1.0.jar`.

## Правила работы с git

- Коммить вместе: изменённые файлы в `_extracted/`, скрипты и пересобранный `lib/DesktopUmagFX-4.1.0.jar` — они должны соответствовать друг другу.
- Не коммить: `jre/`, логи, `*.lck`, `*.tmp`, `*.bak` (уже в `.gitignore`).
- `db/scale.script` и `bin/db/scale.script` меняются при каждом запуске приложения. Не включай их в коммит, если изменение базы не было целью задачи, и не добавляй в них реальные учётные или клиентские данные.
- Не трогай сторонние библиотеки в `lib/` и `_extracted/css/` (JFoenix) без явной просьбы.
- Сообщения коммитов — в стиле Conventional Commits (`feat:`, `fix:`, `docs:`).
- При заметных изменениях поведения обновляй [README.md](README.md).
