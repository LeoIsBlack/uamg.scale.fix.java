# Инструкции для ИИ-агентов

Этот файл читают агенты (Claude Code, Codex, Cursor и др.) перед работой с репозиторием. Описание сделанных улучшений для людей — в [README.md](README.md).

## Что это за проект

Модифицированная сборка десктоп-приложения **DesktopUmagFX 4.1.0** (JavaFX + Spring + Hibernate + HSQLDB) для загрузки товаров на электронные весы (Rongta, CAS, Massa-K, Mertech, Tiger, Штрих и др.).

**Исходников Java в репозитории нет.** Работа ведётся с распакованным JAR: ресурсы правятся как текст, а логика — патчами байткода через Javassist.

## Структура

| Путь | Что там |
|---|---|
| `lib/DesktopUmagFX-4.1.0.jar` | Основной JAR приложения — **результат сборки**, его запускает `.bat` |
| `lib/*.jar` | Зависимости (в т.ч. `javassist`, `commons-io`, нужные скриптам сборки) |
| `_extracted/` | Распакованное содержимое основного JAR — здесь вносятся правки |
| `_extracted/layout/*.fxml` | Разметка экранов JavaFX |
| `_extracted/styles/*.css` | Стили; `dark.css` — тёмная тема |
| `_extracted/kz/umag/scale/**.class` | Скомпилированные классы (часть уже пропатчена) |
| `patch_senior.js` | Патчи байткода (Javassist, запускается под Nashorn) |
| `repack_final.js` | Пересборка JAR из `_extracted/` |
| `bin/DesktopUmagFX.bat` | Запуск приложения (главный класс `kz.umag.scale.app.ScaleApp`) |
| `bin/db/`, `db/` | Локальная база HSQLDB (`scale.script`, `scale.properties`) |
| `configs/libra.properties` | Конфигурация весов |
| `jre/` | Встроенная Java 8 (32-bit), **не в git** — см. ниже |

## Окружение

- Только **Windows**. Приложение использует нативные DLL драйверов весов через JNA.
- Нужна **Java 8** (с JavaFX и Nashorn/`jjs`). Каталог `jre/` исключён из git (`.gitignore`), после клонирования его надо положить в корень вручную — `.bat` ищет именно `jre\bin\java.exe`.
- В `patch_senior.js` и `repack_final.js` **жёстко прописан путь `c:\весы`**. Если репозиторий лежит в другом месте — сначала поправь пути в скриптах.

## Рабочий цикл

1. **Правка ресурсов** — редактируй файлы в `_extracted/layout/` и `_extracted/styles/`.
2. **Правка логики** — добавь патч в `patch_senior.js` и запусти его (классы записываются в `_extracted/`):
   ```bat
   jre\bin\jjs.exe -cp "lib\*" patch_senior.js
   ```
3. **Пересборка JAR**:
   ```bat
   jre\bin\jjs.exe -cp "lib\*" repack_final.js
   ```
4. **Запуск и проверка**:
   ```bat
   cd bin
   DesktopUmagFX.bat
   ```

Автотестов нет. Проверка — запуск приложения и ручной просмотр изменённого экрана; ошибки смотри в консоли и в `logs/`.

## Важные ловушки

- **`repack_final.js` кладёт в JAR только файлы из списка `filesToUpdate`.** Изменил или добавил другой файл в `_extracted/` — добавь его в этот список, иначе правка в JAR не попадёт.
- **`patch_senior.js` не идемпотентен.** Он читает классы из `_extracted/` (уже пропатченные) и вставляет код ещё раз; повторный запуск продублирует вставки `insertBefore`/`insertAfter`. Перед повторным запуском верни затронутые `.class` к исходным (`git checkout -- <файл>` или из оригинального JAR) либо запускай только новый патч.
- **FXML — строго UTF-8 без BOM.** BOM приводит к ошибке `Content is not allowed in prolog`. Осторожно с PowerShell 5.1: `Out-File`/`>` добавляют BOM.
- **Не используй инлайн-стили `style="..."` в FXML** — они перекрывают CSS-классы и ломают тёмную тему. Любой новый стиль светлой темы должен иметь пару в `dark.css`.
- **Javassist-код — это Java 1.4-подобный синтаксис**: без дженериков, лямбд и автобоксинга; параметры метода — `$1`, `$2`; имена классов — полностью квалифицированные.
- Байткод должен оставаться совместимым с **Java 8**.
- **Закрой приложение перед пересборкой** — запущенный процесс держит JAR и файлы базы (`*.lck`).
- `repack_final.js` заменяет JAR на месте. Резервная копия `lib/*.bak` в git не хранится; для отката используй `git checkout -- lib/DesktopUmagFX-4.1.0.jar`.

## Правила работы с git

- Коммить вместе: изменённые файлы в `_extracted/`, скрипты и пересобранный `lib/DesktopUmagFX-4.1.0.jar` — они должны соответствовать друг другу.
- Не коммить: `jre/`, логи, `*.lck`, `*.tmp`, `*.bak` (уже в `.gitignore`).
- `db/scale.script` и `bin/db/scale.script` меняются при каждом запуске приложения. Не включай их в коммит, если изменение базы не было целью задачи, и не добавляй в них реальные учётные или клиентские данные.
- Не трогай сторонние библиотеки в `lib/` и `_extracted/css/` (JFoenix) без явной просьбы.
- Сообщения коммитов — в стиле Conventional Commits (`feat:`, `fix:`, `docs:`).
- При заметных изменениях поведения обновляй [README.md](README.md).
